Invoice Radar — Setup & Ship Guide

Powerhouse Tech · per-client deployment · what to do and how it looks to users

1. What you're shipping

One self-running engine per client, living inside their own Google account. It watches the inbox, reads every invoice with AI, chases politely over WhatsApp/email, and stops the moment a bill is paid. No server to host — Google runs it on a schedule.

2. The workflow (what happens automatically)

1
Capture — invoice arrives via email, photo (Drive), or manual entry. A scan runs every 2 hours.
2
Read — Claude extracts amount, due date & party with a confidence score. Anything unsure lands in a Needs review queue.
3
Chase — Stage 1 (friendly, ≤7d) sends automatically. Stage 2 & Final wait behind an approval gate.
4
Approve — you tap Approve / Snooze / Skip on the firmer nudges. Nothing harsh goes out without you.
5
Reconcile — client clicks the pay link → invoice flips PAID, chasing stops, KPI updates.

4. Steps to ship (per client)

  1. In the client's Google account: create a Sheet → Extensions → Apps Script.
  2. Paste in the engine .gs files + set the manifest from appsscript.json.
  3. Project Settings → Script properties → add secrets: ANTHROPIC_API_KEY, WHATSAPP_TOKEN, WHATSAPP_PHONE_ID (optional DRIVE_INBOX_FOLDER_ID).
  4. Run initialize() once — builds every tab.
  5. Run installTriggers() — wires daily chase (16:00) + 2-hour inbox scan.
  6. Deploy → New deployment → Web app (execute as you, access "Anyone") → use that URL for pay links; point pay.phtech.in at it.
  7. In Gmail, label incoming invoices invoices-inbox (or share a Drive folder for photos).
You do steps 1–7 yourself. Signing into Google, entering API keys, and granting OAuth consent are actions I can't perform on your behalf — they need a human at the keyboard.

5. Make it repeatable

Build the engine once as a Google Sheet template, then "Make a copy" per client and swap only the 3 Script Properties. New client onboarding drops from ~1 hour to ~5 minutes.

Not auto-wired (on purpose): SMS (needs India DLT registration) and Zoho/Tally two-way sync (stubbed hook — enable per client).
